# Моя школа — образовательное PWA для ребёнка 7 лет

Один ребёнок (1 класс, билингва рус/нем), Хромбук с сенсорным экраном. Модули: математика, русский, немецкий.
Чистые HTML/CSS/JS (ES-модули), без фреймворков, сборщика, внешних зависимостей и сетевых запросов. Общаться с владельцем по-русски.

## Как запустить

Нужен любой локальный статический сервер из корня проекта, например:

```bash
python -m http.server 8080
```

Открыть http://localhost:8080/ в Chrome. Service worker работает только на `localhost` или https, поэтому `file://` не подходит.
После первого открытия приложение работает офлайн и устанавливается на полку Хромбука (меню Chrome → «Установить»).
Файлы отдаются сетью в первую очередь, кэш — только запасной вариант, поэтому правки видны сразу после перезагрузки.

## Структура

```
index.html, manifest.webmanifest, sw.js, icons/
core/                  ядро (модули его не импортируют)
  main.js              запуск, переключение экранов, запуск модуля, награды
  registry.js          чтение modules/registry.json и manifest.json, import() модуля, кэширование
  context.js           сборка ctx для модуля
  speech.js            speak(): audio/<язык>/<ключ>.mp3 → Web Speech API
  sounds.js            мягкие звуки (WebAudio)
  rewards.js           звёзды за серию, стикеры, пороги
  storage.js           настройки и прогресс (localStorage), экспорт/импорт JSON
  strings.js           ВСЕ тексты интерфейса ядра
  dom.js               h(), onTap(), button()
  screens/             menu, result, stickers, parent
  styles/              base.css, screens.css
modules/
  registry.json        список id модулей (одна строка на модуль)
  <id>/manifest.json, index.js, style.css, texts.js …
audio/ru/, audio/de/   необязательные озвучки <ключ>.mp3
```

## Контракт модуля

`modules/<id>/manifest.json`: `id` (= имя папки), `title`, `subject` (`math` | `orientation` | `russian` | `german` | `english`), `icon` (эмодзи или файл в папке модуля), `description`, `version`.
Необязательное `glyph` — короткий знак (до 6 символов: `+10`, `5>3`, `Л·П`, `der`) для карточки задания на главном экране; если его нет, показывается `icon`. Список знаков — `design/README.md`, раздел 9.1.
Необязательно: `series: false` (модуль без серии — «Знакомство» в English: у экрана нет дорожки лапок), `stars: false` (модуль не даёт звёзд: экран результата без звёздочек и счёта, только печать «Готово!»; у «Знакомства»), `challenge` (только у `modules/challenge`: разделы сложных заданий, см. ниже), `styles` (список css), `files` (остальные файлы модуля и аудио — чтобы они попали в офлайн-кэш), `cycle` (id круга, см. ниже), `voice: true` (включить озвучку только для этого модуля, даже если глобально она выключена).

`modules/<id>/index.js` экспортирует `start(ctx)`. Функция должна вернуться быстро (не ждать конца серии) и может вернуть функцию очистки. `ctx`:

| Поле | Назначение |
|---|---|
| `container` | DOM-корень модуля |
| `voice` | `true`, если озвучка включена (`core/config.js`). При `false` `speak()` ничего не произносит, но «длится» как речь; модуль скрывает кнопку «повторить» |
| `speak(text, lang, key?)` | озвучка, `lang` — `'ru'` или `'de'`; Promise по окончании речи. Файл: `audio/<lang>/<key>.mp3`; без `key` ключ строится из текста |
| `sound(name)` | `tap`, `correct`, `hint`, `star`, `done` |
| `settings` | `{ seriesLength, speechRate, volume }`, только чтение |
| `hard` | ключи «трудных» заданий этого модуля из прошлых серий, только чтение |
| `level` | с какого уровня начинать серию: уровень, на котором закончилась прошлая серия, минус один (разогрев); `null` — серий ещё не было (берите свой `START_LEVEL`). Модуль передаёт итоговый `level` в `finish({ …, level })`, ядро запоминает его в `progress[id].level`. Повышение уровня — после `CLEAN_TO_LEVEL_UP = 3` верных подряд |
| `words.pick(items, keyOf)` | выбрать слово с учётом выученных: `keyOf(item)` даёт ключ вида `ru:кот`; выученные (и ещё не пора повторять) слова не выпадают, новые и непрочные идут чаще; если все выучены — любое. `words.size(ns, n)` — сообщить, сколько слов в банке языка (для отчёта) |
| `task({ ok, level, key? })` | задание закончено (первый заход, не повтор в конце серии): `ok` — верно с первой попытки, `level` — уровень сложности модуля. Нужно для журнала серий и отчёта родителю; вызывается в цикле серии сразу после `const firstTry = await playTask(...)` (`ctx.task({ ok: firstTry, level })`). Время на задание считает ядро. Если передан `key` (слово), ядро обновляет учёт этого слова (`storage.recordWord`) |
| `finish({ correct, total, mistakes })` | конец серии; `mistakes` — `[{ key, label }]`. Звёзды, прогресс и экран результата делает ядро |

## Круги и супер-наклейки

Модули с одинаковым `cycle` в манифесте образуют круг. Сейчас шесть кругов (**правило: у каждого модуля любого раздела, английского тоже, есть `cycle`** — `check.mjs` это проверяет): `orientation` (`left-right`, `left-right-other`, `mental-rotation`, `top-view`, `cubes`), `math` (вся математика: `addition-10`, `addition-20`, `subtraction-10`, `subtraction-20`, `compare-numbers`, `word-problems`, `money`), `russian` (`reading-ru`, `reading-phrases`, `reading-sentences`, `reading-pick`, `reading-long`) `german` (`reading-de`, `reading-phrases-de`, `reading-sentences-de`, `reading-pick-de`, `reading-long-de`, `german-articles`) и `english` (`english-words`, `english-quiz`, `english-say`, `english-phrases`, `english-sentences`). Супер-наклейки всех кругов копятся в одной общей сказке.
Завершённая серия закрывает кнопку модуля (серая плитка с ✓), остальные остаются доступны в любом порядке.
Когда пройдены все включённые модули круга, ядро выдаёт супер-наклейку, открывает все кнопки, и круг начинается заново (`core/cycles.js`).
Модули без `cycle` (сейчас таких нет, кроме модуля сложных заданий) доступны всегда. Закрытый модуль нельзя повторить, в том числе кнопкой «Ещё раз». Модуль, выключенный родителем, в круг не входит.
Если все доступные модули круга оказались пройдены (родитель отключил непройденный), круг молча начинается заново без награды (`healCycles`), чтобы кнопки не застряли закрытыми. Прежние круги `arithmetic` и `numbers` при чтении сохранения сливаются в `math` (`CYCLE_ALIASES` в `core/storage.js`).
Прогресс круга и число супер-наклеек хранятся в `localStorage` вместе с остальным прогрессом.
Супер-наклейки собираются в **мирах** (`WORLDS` в `core/rewards.js`): «Моя сказка» (единорог, принцесса, замок, диван…), «Подводный мир» (русалки), «Волшебный лес», «Сладкая страна», «Зоопарк», «Зимняя сказка» (Рождество), «Цирк», «Космос» (всего 8 миров, 96 супер-наклеек). Каждый мир — сцена с 12 предметами (положение, размер, названия на русском и немецком заданы в данных). Когда мир собран, открывается следующий; после последнего миры повторяются, лишние наклейки лежат отдельным рядом. При получении на экране результата вылетает окно с поздравлением («Ты получила «Русалка»! Твой подводный мир растёт.»), а при завершении мира — сообщение о новом мире.

## Книжный стиль модулей (шаг 8)

Модули переводятся на «сказочную книжку» по группам: сначала раздел `orientation` (`left-right`, `left-right-other`, `mental-rotation`, `top-view`, `cubes`); остальные разделы — в старом виде и ждут своей очереди. Правила: `style.css` модуля берёт цвета и тени из токенов `base.css` (`--book-card`, `--book-ink`, `--book-shadow`, `--book-done`, `--math-ribbon`…), вопрос — `var(--font-hand)`, ответы — бумажные карточки одного цвета (верный — зелёное пятно, неверный бледнеет), без `:hover`; собственные точки прогресса `.xx-dots` скрывает ядро (дорожка лапок). Большие эмодзи (главная картинка крупнее ~120 px) заменяются плоской SVG-иллюстрацией в `index.js` (фильтр `wcS` общий), эмодзи-картинки к словам ограничиваются 120 px и рисуются как наклейка (`filter: url(#stk)`). Новых файлов в модуле нет, поэтому `files` в манифесте не менялся.

## Правила для новых модулей

- Добавление модуля = папка `modules/<id>/` + одна строка в `modules/registry.json`. Файлы `core/` не правим.
- Из `core/` ничего не импортировать — только `ctx`. Свои файлы модуль импортирует относительными путями.
- Задания генерируются кодом, не фиксированным списком. Ошибочные задания повторяются в конце серии.
- `correct` — ответы с первой попытки. Ошибка = мягкая подсказка и ещё одна попытка; никаких красных крестов и грустных звуков.
- В каждом задании есть кнопка «повторить» (повторный вызов `speak`); при `ctx.voice === false` она скрыта (`repeatBtn.hidden = !ctx.voice`).
- Тексты модуля — в `modules/<id>/texts.js`, не разбросаны по коду. Немецкий раздел целиком по-немецки (тексты, заголовок плитки, озвучка).
- Модуль не обращается к сети и не использует внешние библиотеки, шрифты, картинки по URL.
- Ключи `hard`/`mistakes` должны быть стабильными и разбираемыми обратно (например, `3+4`).
- Свои стили — с префиксом модуля (`.a10-…`), чтобы не пересекаться с другими модулями и ядром.

## Требования к детскому интерфейсу

- Сенсорное управление через Pointer Events. Цели касания не меньше 64 px (лучше 100+ для основных ответов). Никаких `:hover`.
- Перетаскивание пальцем там, где оно уместно; обычное касание должно работать всегда. Клавиатура (Enter/Пробел) — запасной вариант (`click` с `detail === 0`).
- Во время игры нет прокрутки и зума: `touch-action: none`, `overflow: hidden`.
- Ландшафт, всё помещается на экран 1280×720 без прокрутки. Размеры в `vh`/`vw`/`clamp()`.
- Крупные шрифты, минимум текста, смысл передаётся картинками и голосом.
- Кнопка «домой» (🏠) рисуется ядром слева сверху; у `container` боковые поля 96 px — не занимайте их.
- Тон позитивный: поощрение вместо оценки, мягкие звуки.
- Никакой рекламы, регистрации, аналитики и отправки данных.

## Ядро: что важно помнить

- Новый файл в `core/` нужно дописать в `CORE_FILES` в `sw.js`, иначе он не попадёт в офлайн-кэш при первой установке.
- **Рамка задания** (`play()` в `core/main.js`): одна бумажная страница книги на всё окно (`createSheet()` в `core/screens/book.js`; при открытии бумага с обложкой «переворачивается» классом `.page-turn`, содержимое модуля в повороте не участвует), слева сверху бумажный ярлычок «домой» (`homeTag`, 72×72 как раньше), сверху по центру дорожка акварельных лапок к косточке (`core/screens/series-track.js`: лапок `seriesLength`, закрашивается по вызову `ctx.task`; у сложного задания и модулей с `series: false` её нет). Собственные серые точки модулей (классы `*-dots`) на экране с дорожкой скрыты правилом в `book.css`, модули для этого не менялись. **Экран результата** (`core/screens/result.js`) — разворот книги: слева собака ребёнка радуется, справа звёзды появляются по одной (`.rs-star`) и печать `.stamp`. Для ответов и вопроса в стиле книги есть заготовка `.book-question` / `.book-answer` (+ `.is-right`, `.is-wrong`) в `book.css`: общих классов ответов в `core/styles` не было — каждый модуль рисует свои (`a10-answer`, `rp-card`, …); их перевод — отдельный шаг.
- **Главный экран — «сказочная книжка»** (`core/screens/menu.js` на общем компоненте `core/screens/book.js`: стол, обложка, две страницы, корешок, бумага; `createBook({ top, left, right })`, `counters`, `noteButton`, `lockButton` — им же будут пользоваться остальные экраны). Рисунки — `core/screens/book-art.js`, фильтры — `core/art/filters.js` (ставятся при старте), общие классы (`.hand`, `.paper-card`, `.tape`, `.ribbon`, `.stamp`, `.page-turn`, `.s-<предмет>`) — `core/styles/book.css`, токены цвета и шрифты — `core/styles/base.css`, шрифты — `fonts/` (Andika, Caveat, лицензия OFL). Слева — собака ребёнка (первая из `dogs()`, рисует `drawDog`; пока своей нет — собака-проводник Бобик, `guideDog()` в `book.js`, не купленная: во дворе её нет) и дорожка к косточке (`challengeProgress()` в `core/challenges.js`: `звёзды % 25`); справа закладки по `STR.subjectOrder`, выбранная глава — в `sessionStorage` через `storage.uiState`. Звёзды на карточке задания — не отдельное хранилище, а `starsFor` от доли верных за всё время (`moduleProgress`); пройденный в круге модуль остаётся яркой карточкой с печатью «Готово!».
- Разделы меню сейчас: математика, пространственное мышление (`orientation`, бывший «Право и лево»; id раздела и круга не менялись), русский язык, Deutsch. Немецкий раздел устроен как русский: `reading-de`, `reading-phrases-de` и `reading-sentences-de` — копии русских модулей со своими словарями (`words.js`, `data.js`), текстами по-немецки и озвучкой `'de'`. Прилагательное в `reading-phrases-de` — без артикля (grüner Hund, grüne Katze, grünes Haus).
- Новый предмет — запись в `STR.subjects` и `STR.subjectOrder` в `core/strings.js` (поле `lang` — язык служебных текстов ребёнку).
- Все тексты ядра — только в `core/strings.js`.
- Прогресс лежит в `localStorage` под ключом `school-app-v1`; экспорт/импорт — на экране для родителя.
- «Трудное» задание забывается после 3 серий, в которых оно было предложено и решено без ошибки. Каждой серии ядро даёт модулю до 2 самых частых трудных заданий (`ctx.hard`) и отмечает их как предложенные.
- Звёзды: ≥90% верных — 3, ≥70% — 2, иначе 1 (`starsFor` в `core/rewards.js`). Звёзды — валюта: в магазине (вкладка «Магазин» на экране «Наклейки») ребёнок сам покупает наклейки. Каталог — 9 альбомов по 12–24 наклейки, всего 120 (`ALBUMS`): цены 5 (первый альбом), 6, 10, 14 и 20 звёзд по редкости. На счету = заработано (`stars`) − потрачено (`spent`). Купленные наклейки (`owned`) хранятся вместе с прогрессом. Прежний прогресс переносится при первом запуске: за каждые 5 звёзд до 24 наклеек считаются купленными.
- **Экран «Наклейки» — разворот книги** (`core/screens/stickers.js` на `createBook`, стили — `core/styles/stickers-book.css`): слева мир супер-наклеек (небо и холм из `WORLDS` акварелью, предметы на местах, стрелки между открытыми мирами), справа закладки «Коллекция» (страница альбома: купленные наклейки в цвете, остальные карандашом) и «Лавка наклеек» (3×4 бумажных карточек, цена звёздами на жёлтой плашке, на купленных печать «Есть!», выбор → кнопка «Купить»; купленная наклейка с отскоком и искрами встаёт на место). Купленное эмодзи рисуется фильтром `stk` (белая кайма и тень), некупленное — `pencil` (оба в `core/art/filters.js`). Каталог (`ALBUMS`, `WORLDS`, цены) не менялся. Окно поздравления супер-наклейки (`result.js`) — бумажная карточка на скотче.
- **Служебные экраны на бумаге книги**: проверка для взрослых (`gate.js`) и экран родителя (`parent.js`) оформлены в `createSheet({ className: '… service-sheet' })` (содержимое лежит над слоем бумаги, правило `.service-sheet > :not(.sheet-paper)` в `screens.css`); логика не менялась, экран родителя строже и мельче и единственный прокручивается. Экран отдыха (`limit.js`) — ночной двор: луна и звёзды (маленькие SVG с `wcS`), холм, спящий Бобик (`guideDog()` с классом `sleeping`), «Z z z»; большие фоны без фильтров. Цвета PWA (`theme_color`, `background_color` в `manifest.webmanifest`, `<meta name="theme-color">`) — цвет стола `#e4ece6`; иконку приложения не трогали.
- **Скорость акварели** (слабый процессор Хромбука): (1) фактура бумаги не фильтр, а картинка — `core/art/textures.js` один раз при старте рисует шумовую плитку 512×512 (SVG → canvas → blob) в CSS-переменную `--tex-paper`, стол и бумага берут её фоном; пока не готова — гладкая бумага; (2) SVG-фильтры только на небольших элементах (рисунки, наклейки, собака), у `feTurbulence` `numOctaves` 1–2; (3) все бесконечные анимации (хвост, дыхание, облака, звёзды) ставятся на паузу, когда вкладка скрыта (`html.app-hidden`) и когда ребёнок минуту ничего не касался (`html.app-idle`, `CALM_MS` в `main.js`), а при `prefers-reduced-motion` отключены; (4) крупные слои — `will-change: transform` (блок «Скорость» в конце `book.css`). Новые бесконечные анимации нужно добавлять в этот список остановки; новые большие фоны — без фильтров.
- Озвучка целиком включается и выключается флагом `VOICE_ENABLED` в `core/config.js`; отдельному модулю её включает `"voice": true` в манифесте (так сделан раздел English) (сейчас `false`: звука речи нет, настройки голоса у родителя скрыты). Остальные звуки (`sound`) работают.
- Голос синтеза для `ru` и `de` родитель выбирает на экране «Родителям» (список голосов браузера, онлайн-голоса помечены); по умолчанию — автоподбор в `core/speech.js`. Без интернета онлайн-голос заменяется локальным.
- Скорость речи (`speechRate`) применяется к синтезу; mp3-файлы воспроизводятся как записаны.

## Усложнённые упражнения по чтению (русский)

Два модуля для ребёнка, который уже уверенно читает; входят в круг `russian` (круг теперь из пяти модулей). Оба без озвучки, как и весь русский раздел. Прежние три модуля остались как лёгкая основа. Третий вариант («Собери слово из букв») владелец отклонил как слишком простой и убрал. Немецкие копии — `reading-pick-de` («Lesen und Bild finden») и `reading-long-de` («Lange Sätze»), круг `german`; устроены так же, но берут слова и предложения из немецких модулей, озвучка `'de'`.

- `reading-pick` («Читаем и ищем картинку»): показано слово / два слова / предложение, нужно выбрать картинку из 3–4. Уровни: слово до 5 букв (3 картинки) → слово до 8 букв (4, похожие по написанию) → «красный кот» (тонированные эмодзи, как в `reading-phrases`) → предложение (act/place, две эмодзи в карточке). Ключи трудных: `w:кот`, `p:red:кот`, `s:Кот пьёт молоко`. Данные берёт из соседних модулей (`../reading-ru/words.js`, `../reading-phrases/data.js`, `../reading-sentences/data.js`) — это исключение из правила «модуль самодостаточен», как у `english-quiz`; файлы перечислены в `files` манифеста.
- `reading-long` («Длинные предложения»): копия механики `reading-sentences` (собрать предложение из слов), но 5–6 слов. `data.js` строит предложения кодом из `../reading-sentences/data.js`: `two` («Кот пьёт молоко и спит»), `adj` («Весёлый кот спит на мягком диване»; прилагательные согласованы по роду героя и падежу места, не про цвет), `pair` («Кот и собака спят на траве»). Лишние слова верхнего уровня — не тот род/падеж/число или спорят с картинкой. Родов героев (`GENDER`) и форм прилагательных к местам (`PLACE_ADJ`) в `data.js` должно хватать на все герои и места из `reading-sentences`, иначе предложение молча пропускается.
- `reading-long-de` («Lange Sätze»): 6 слов. `two` («Die Katze trinkt Milch und schläft»), `adj` («Der große Hund läuft im Wald»: после артикля прилагательное на -e во всех трёх родах, лишнее слово — форма на -n; цвета не используются), `pair` («Hund und Katze spielen im Garten»; лишнее слово — глагол в единственном числе). Тексты на немецком, кроме комментариев в коде.

### Банки предложений и контроль повторов слов («Собери предложение», «Длинные предложения», ru и de)

Ребёнок быстро выучивает слова, которые стоят почти в каждом предложении («мальчик», «девочка», «trinken», «laufen»), и собирает предложения по привычке, а не читая. Поэтому повторы слов **измеряются и ограничиваются** — в банке и при выборе задания.

- **Банки** (`reading-sentences/data.js`, `reading-sentences-de/data.js`, а из них строятся `reading-long`, `reading-long-de`): герои, предметы, места, глаголы заданы компактно (`S(...)`, словари `OBJECTS`, `PLACES`, `SHORT_VERBS`). Новое слово или картинку дописываем в словарь один раз, герой ссылается на него словом; нет картинки в словаре — `data.js` падает с понятной ошибкой. Сейчас: ru — 711 предложений (356 разных слов), de — 836 (338), длинные ru 659 (676), de 602 (483); до переделки было 101 / 95 / 128 / 100 разных слов, а «и», «спят», «играют», «бегут» (и «und», «schlafen», «spielen», «laufen») стояли в 22–73% предложений, потому что пар «X и y …» было 468 (все со всеми, три глагола). Теперь пары собираются по группам умений (сухопутные, птицы, водные, люди, человек и его друг-животное) и не «все со всеми»; глаголов десятки (жуёт, грызёт, клюёт, щиплет, шагает, бродит, живёт…; rennt, geht, schleicht, trabt, wandert, spaziert…).
- **Предложения без картинки** (`kind: 'free'`, `nopic: true`, `scene: []`, `extras: []`): когда подходящей картинки нет (имена — картинка к «Маше» ничем не лучше «девочки», погода и времена года, привычки животных, чувства, школа). Сейчас в ru 110 и в de 88 коротких, в длинных по ~40. Попадаются иногда: с уровня 1 примерно каждое пятое задание (`FREE_FROM_LEVEL`, `FREE_SHARE` в `picker.js`); у них 3–6 слов, одинаковых слов нет, лишней фишки нет (по картинке её не отличить); в модуле при пустой картинке блок `.xx-scene` скрыт (`.empty`). Ошибка таких заданий в журнале и отчёте подписана «📝 …». Новое предложение без картинки — строка в `FREE` в `data.js`.
- **Выбор задания** — `reading-sentences/picker.js` (общий для четырёх модулей, перечислен в `files`; исключение из правила «модуль самодостаточен»). Из 28 случайных кандидатов берётся тот, у которого меньше «затёртых» слов: штраф за слово, которое уже было в этой серии (`SERIES_PENALTY`), за слово, с которым ребёнок уже не раз собирал предложения без ошибок (`STATUS_PENALTY`: выучено — реже), и за частоту слова в банке (`SHARE_PENALTY`: частые слова реже, редкие чаще). Служебные слова (предлоги, «и», артикли — `IGNORE` в каждом `index.js`) не считаются. После предложения, собранного без ошибок, каждое слово отмечается в учёте слов ядра (`rsw:слово` для русского, `dsw:слово` для немецкого, `ctx.words.mark`); в блоке «Слова» у родителя это строки «…в предложениях (собирает)». Симуляция 400 серий по 10 заданий: самые частые слова раньше были в 11–16% заданий (ru «ест» 16%, «девочка» 14%; de «laufen» 11%), теперь в 3–4%; слов, повторившихся внутри серии, было ~6 на серию, стало 0; разных слов за 400 серий было 96 (ru) и 89 (de), стало 347 и 321.
- **Контроль** — `node tools/word-freq.mjs [N]` печатает по каждому банку число предложений по видам, разных слов, самые частые слова (доля предложений, где слово есть) и сколько слов встречается не больше двух раз; `check.mjs` использует тот же расчёт и **падает**, если «настоящее» слово (не служебное) стоит больше чем в `MAX_SHARE` = 10% предложений банка (ориентир — до 8%), а также если у двух предложений одного вида одинаковая картинка (ответ неоднозначен), если у предложения без картинки не 3–6 слов или есть `scene`/`extras`, если слово повторяется внутри предложения. Прежний банк расширяйте так: сначала новых героев, предметы, глаголы и предложения без картинки, потом смотрите `word-freq.mjs`; если одно слово «разрослось», режьте его предложения или добавляйте рядом другие.
- **«Длинные предложения» — не только «кто-то делает что-то»** (`reading-long`, `reading-long-de`): кроме `two`, `adj`, `pair` есть виды, которые учат разному — `have` (описание: «У слона очень длинный хобот», «Der Elefant hat einen langen Rüssel»; с картинкой героя), `ask` (вопрос со знаком «?»: «Где обычно спит наш кот?», «Wo schläft die kleine Katze?»; с картинкой), `because` («Заяц бежит, потому что боится волка» / «Mia weint, denn sie ist traurig»: запятая), `contrast` («Днём кот спит, а ночью гуляет» / «Hunde bellen, aber Katzen miauen»), `compare` («Слон гораздо больше, чем мышь» / «Elefanten sind größer als Mäuse»), `order` («Сначала мы завтракаем, потом играем» / «Zuerst kommt der Winter, dann Frühling»). Знак препинания стоит в конце слова («спит,», «кот?») и виден на фишке; одно слово с запятой и без — для учёта слов одно и то же (`plain` в `picker.js`). `because`, `contrast`, `compare`, `order` без картинки (`nopic`) и без лишних фишек, у `have`/`ask` картинка есть, лишних фишек нет. Уровни (`LEVEL_KINDS`): 0 — `two` и `have`; 1 — `adj`, `ask`, `pair`; 2 — `compare`, `contrast`, `order`, `because` (весь уровень без картинок: чистое чтение); 3 — все девять видов вперемешку. Вид выбирается **поровну** (сначала вид, потом предложение: `picker.pick`), иначе самые многочисленные виды (`two`, `adj`, `pair` по 150–170 предложений) забили бы вопросы и «потому что» (по 15–25). Кроме них с уровня 1 примерно каждое пятое задание — `free` (имена, погода, привычки). У всех длинных предложений 5–6 слов (`check.mjs`). Новую фразу вида `have`/`ask`/… добавляем в соответствующий список в `data.js`; в `have` и `ask` герой должен быть в `HEROES`.
- В `reading-long`/`reading-long-de` герой, его род и «что умеет» берутся из `HEROES` (`reading-sentences*/data.js`; `reading-long` — ещё `PLACE_ADJ`), поэтому новый герой или место попадают и в длинные предложения; на повторы слов там стоят лимиты (`limiter`: глагол, предмет/место и герой не чаще N раз в `two` и `adj`), пары берутся вразброс (`PAIRS_PER_PLACE`), а картинка у каждого предложения вида одна.

## Сложные задания, косточки и собака

**Косточка 🦴** — вторая валюта. Её дают только за сложное задание; тратится она на собак, корм и пакетики (экран собаки).

### Сложные задания (`core/challenges.js`, модуль `modules/challenge`)
- Каждые **25 заработанных звёзд** (всего заработано, `storage.stars()`, а не остаток после покупок наклеек) в случайном разделе появляется сложное задание. Звёзды, заработанные до появления этой возможности, не учитываются (при первом запуске `milestone` = текущие звёзды / 25). **Первые три задания выдаются сразу** (в трёх разных случайных разделах), чтобы хватило косточек на первую собаку.
- В разделе висит **не больше одного** задания. Если свободных разделов нет, задание ждёт (`owed`) и появится, когда раздел освободится. Раздел, где родитель выключил все модули, задание не получает.
- Задание — особая золотая плитка с 🦴 первой в своём разделе (`challengeTile` в `core/screens/menu.js`); пройдено — плитка исчезает. Вне кругов и супер-наклеек, звёзд не даёт, в статистику родителя и список модулей не попадает (в `app.manifests` его нет, оно лежит отдельно в `app.challenge`). В родительском разделе для заданий ничего нет.
- Прохождение: текст 3–4 предложения остаётся на экране, **один вопрос**, 3–4 варианта. Ошибка = мягкая подсказка (подсвечивается нужное предложение), ещё попытка; косточка за любое прохождение. После — экран «Косточка!» с кнопками «К собаке» / «В меню» (`renderChallengeResult`, язык раздела: русский или немецкий). На экране результата обычной серии, где появилось новое задание, показывается подсказка «Появилось сложное задание: …».
- Состояние в `storage.challenges()`: `ready`, `milestone`, `owed`, `pending` (`{ раздел: { seed } }`), `used` (пройденные тексты по разделам). `seed` фиксирует задание: если выйти и вернуться, текст тот же. `core/challenges.js`: `syncChallenges(app)` (вызывается при показе меню и после каждой серии), `challengeInfo`, `completeChallenge`.
- Модуль `modules/challenge` один на все разделы: манифест с полем `challenge.subjects` (название и значок плитки каждого раздела, `voice: true` у английского), `ctx.challenge = { subject, seed, used }`. Задания по разделам:
  - **русский** (`pools/ru.js`, 14 рассказов) и **немецкий** (`pools/de.js`, 14, всё по-немецки): рассказ и вопрос «кто / где / сколько / что»; у каждого `answer` (номер верного), `clue` (подсвечиваемое предложение);
  - **математика** (`pools/math.js`): задача-история в 3 предложения, два действия, числа до 20, 6 шаблонов (подарили-отдали, две коробки, покупка и сдача, возраст, страницы, ступеньки), склонения через `plural`;
  - **право и лево** (`pools/orientation.js`): «четыре зверя на скамейке» (кто справа/слева, кто с краю) и «куда улетела пчёлка» (где она относительно улья);
  - **английский** (`pools/en.json`, 12 рассказов): рассказ из 3 предложений слушается голосом Sonia (`audio/en/ch-<id>-story.mp3` и `-q.mp3`, делает `tools/make_audio.py`), ответ — картинка, цвет или число; английский текст на экране, перевод — при включённом переводе у родителя.
- Новый рассказ: добавить запись в пул (русский/немецкий/английский), для английского запустить `python tools/make_audio.py`; `node tools/check.mjs` проверяет число предложений, варианты, номер верного, подсветку, озвучку и прогоняет генераторы математики и «право-лево» на 400 зерен.

### Собака (`core/screens/dog.js`)
- Значок 🐶 с числом косточек на счету — справа вверху на главном экране (`dogButton` в `core/screens/menu.js`) → экран собаки (`app.go.dog`, `screenKind = 'dog'`; лимит времени действует как в меню).
- Экран собаки: слева двор, справа косточки, кнопки и магазин; выбор собаки — слева картинка, справа порода, цвет, имя (готовых имён 6), возраст (0 — щенок … 15; картинка меняется: щенок меньше, 10+ — седая мордочка). Рисунок собирается кодом как SVG (`drawDog` в `core/dogs.js`), внешних картинок нет. Собака нарисована по `design/sketch/Pup.dc.html`: шесть пород с акварельными градиентами, оттенки считаются из окраса (`palette`: `mix`, `luminance`, особые правила хаски и овчарки). Рисунок лежит в координатах эскиза 300×340 внутри групп `scale(0.8)`, а холст остался 240×270 — поэтому анимации (`dog.css`) прежние; у хвоста точка поворота задана в самом рисунке (у каждой породы свой корень), у `dog-paw-r` тоже, у глаз и языка точки поворота в координатах эскиза (см. комментарий в `dog.css`). У каждого рисунка свои id градиентов (`pup-<порода>-<окрас>-<ошейник>-<номер>-`); акварельный фильтр `wcDog` включён по умолчанию, `drawDog({ …, paint: false })` его отключает. Старые наряды (`outfitSvg`) сдвинуты под новую голову внутри `drawDog` (`outfitHead`, `neckFit`); новые наряды из `Pup.dc.html` — следующий шаг.
- Цены: первая собака — 3 косточки (`DOG_PRICES` в `core/dogs.js`); цены 3, 5, 10 косточек по порядку покупки (если разрешить больше трёх собак, дальше +5: 15, 20, 25…); всего собак до 3 — на столько мест во дворе.
- Живая собака: части SVG (`dog-tail`, `dog-body`, `dog-head`, `dog-eyes`, `dog-tongue`) анимируются в `core/styles/dog.css` — виляет хвостом, дышит, моргает, наклоняет голову, высовывает язык; при `prefers-reduced-motion` анимации отключаются. Касание собаки — она подпрыгивает, вылетают сердечки.
- **Экран собаки — разворот книги** (`core/screens/dog.js` на `createBook`, стили поверх `dog.css` — `core/styles/dog-book.css`, рисунки двора, шкал, миски — `core/screens/dog-scene.js`): слева имя и порода, акварельный двор (забор, лужайка, декор, до трёх собак, какашки, миска, реплика-пузырь) и четыре шкалы со словом («отлично»/«хорошо»/«маловато»/«очень мало»); справа тканевые закладки вкладок (цвета предметов `s-*`) и бумажные карточки действий со скотчем (`action()` делает карточку из «эмодзи название» и счётчика). Пока собаки нет — пустая будка и «Скоро здесь будет твой друг». Выбор собаки — бумажные карточки шести пород, справа окрас, имя и возраст. Мини-игры (`core/dog/*.js`) и выбор собаки идут на одностраничной рамке `createSheet` (класс `dog-sheet`), их механика не менялась; мытьё рисует пузыри стилями, ночь в «Спать» — тёмная акварель с луной и звёздами. **Экран собаки всегда без прокрутки** (проверено на 1024×600, 1280×720, 1366×768; `overflow-y: auto` у `.dog-content` — только запасной вариант для очень низкого окна). Новые элементы на этом экране нужно проверять на то, что `scrollHeight` ≤ `clientHeight`.
- **Все купленные собаки стоят во дворе вместе** (до 3; размер зависит от числа); новая добавляется к прежним и становится выбранной. Собака выбирается касанием (метка ▼ над именем, касание ещё и гладит); корм и уборка действуют на выбранную. `id` собаки уникален.
- Двор: кнопки «Покормить» и «Убрать» со счётчиками, магазин: **1 🦴 = 5 банок корма**, **1 🦴 = 5 пакетиков** (`PACK_PRICE`, `FOOD_PACK`, `BAG_PACK` в `core/dogs.js`). Покормить: тратится банка, собака ест (2,6 с, «Ням-ням!»), потом «делает дела» (1,5 с) и во дворе падает какашка 💩 (`dog.poops` растёт сразу, на экране появляется после анимации). Убрать: касание на какашке или кнопка «Убрать», тратится пакетик. Больше `MAX_POOPS` = 4 какашек у одной собаки не бывает — пока их не уберут, кормить её нельзя («Сначала убери за собакой!»). Нет корма / пакетиков — подсказка со ссылкой на магазин.
- **Два набора данных о собаках: рабочий и тестовый.** Рабочий (в корне состояния: `bones`, `bonesSpent`, `dogs`, `food`, `bags`) — для ребёнка, на главном экране. Тестовый (`state.test`, та же форма) — для проверки новых возможностей: в разделе для родителя карточка «Тестовая собака» открывает тот же экран собаки (`app.go.dogTest()`, `renderDog(app, { scope: 'test' })`) со своими собаками и косточками, с панелью «ТЕСТ +1 🦴 / +5 🦴 / Сбросить тест» в шапке; «Назад» возвращает на экран родителя без проверки для взрослых. Наборы друг с другом не связаны; тестовый не сбрасывается кнопкой «Сбросить прогресс».
- Хранение (`core/storage.js`): `storage.dogApi('real' | 'test')` возвращает `bones()`, `bonesBalance()`, `addBones()`, `dogs()`, `buyDog()`, `food()`, `bags()`, `buyFood()`, `buyBags()`, `feedDog()`, `cleanPoop()` и `reset()` (сбрасывает только тестовый набор). Короткие `storage.bones/addBones/bonesBalance` — рабочие (меню, сложные задания). `dog` = `{ id, name, breed, color, age, poops }`, проверяются `cleanDog`. Состояние также хранит `challenges` и `dogsVersion`; экспорт/импорт их учитывают.

## Деньги (`modules/money`)

Деньги в **евро**, только настоящие номиналы: монеты 1 и 2 €, банкноты 5, 10, 20, 50 и 100 € (`COINS`, `NOTES` в `index.js`; монеты 5 и 10 € и банкнот 1 € не бывает — не добавлять). Центы пока не используются: суммы в целых евро. Банкноты нарисованы стилями (цвет по номиналу: 5 серая, 10 красная, 20 синяя, 50 оранжевая, 100 зелёная; дизайн настоящих купюр не копируется), монеты 1 и 2 € двухцветные, 2 € крупнее. Три вида заданий: «сколько всего денег», «заплати ровно N €» (касанием или перетаскиванием в кошелёк), «сдача». Уровни (`LEVELS`): 0 — сумма до 10 € (монеты 1, 2 и банкнота 5); 1 — до 20 € (с банкнотой 10); 2 — плюс «заплати»; 3 — «заплати» и «сдача»; 4–6 — суммы кратны десяти (банкноты 10, 20, 50, 100): «сколько всего», «заплати», «сдача» со 100 € или 50 €. Для сумм до 20 € в лотке «заплати» монеты 1, 2 и банкноты 5, 10; для больших — банкноты 10, 20, 50, 100. Ключи «трудных» заданий — JSON задания (`{"k":"count","c":[50,20]}`); старые ключи с номиналами рублей при чтении проверяются по допустимым значениям и отбрасываются, если не подходят.

## Пространственное мышление (раздел `orientation`)

Прежний раздел «Право и лево» переименован (`STR.subjects.orientation` в `core/strings.js`); к двум прежним модулям добавлены три прототипа — по просьбе владельца сначала посмотреть и оценить. Они входят в круг `orientation` (чтобы выключить, родитель снимает галочку модуля в блоке «Модули»). Все три строят задания из числа `seed` (ключ `уровень:seed`), поэтому «трудное» задание повторяется точно таким же; уровень помнится между сериями; ввод цифрами — общая клавиатура `addition-10/keypad.js`.

- `mental-rotation` («Повороты»): мысленное вращение. Дана фигура из клеток; среди вариантов нужно найти такую же, только повёрнутую на 90/180/270°. Неверные — зеркальное отражение (его поворотом не получить, форма проверяется кодом) и фигура с одной переставленной клеткой. Уровни: 0 — 4 клетки, 3 варианта; 1 — 5 клеток, есть зеркальная; 2 — 5 клеток, 4 варианта; 3 — 6 клеток (поле 4×4), 4 варианта. Подсказка после ошибки: фигура сама поворачивается нужным образом (CSS), после второй ошибки верный вариант подсвечивается; после верного ответа фигура поворачивается тоже.
- `top-view` («Вид сверху»; бывшие «Тени и вид сверху» — задание с тенями убрано как слишком простое): показан предмет или геометрическое тело сбоку, нужно выбрать, как оно выглядит сверху. Уровни: 0 — предметы попроще (мяч, кубик, домик, пирамида), 3 варианта; 1 — все предметы (мяч, банка, конус, кружка…), 4 варианта; 2 — геометрические тела (куб, цилиндр, пирамида, шестигранная призма, бублик, шар), 3 варианта; 3 — вся геометрия, 4 варианта: тела стоят и лежат (цилиндр и конус на боку сверху выглядят иначе, чем стоя: прямоугольник и треугольник вместо круга; призма-«палатка», брусок). Рисунки — SVG в `data.js` (`SOLIDS`: `front` — спереди, `top` — сверху; объёмные тела строятся функциями `box`, `pyramid4`, `hexPrism`, `prismTent` по 3D-координатам в изометрии, остальное нарисовано вручную; `POOLS` — пулы по уровням). У каждого вида сверху свой `topKey`; два варианта с одинаковым `topKey` вместе не показываются (иначе два верных ответа: например, цилиндр стоя и шар оба круглые, брусок и цилиндр лёжа оба прямоугольные). Тела, которые можно спутать в изометрии (треугольная пирамида и четырёхугольная), в набор не включены. Подсказка: картинка наклоняется («смотрим сверху»); для лежащих тел — подсказка «лежит или стоит?». Ключ задания — `t:id`.
- `cubes` («Кубики»): пять уровней. 0 — сколько кубиков (постройка 2×2–2×3), ответ из трёх; 1 — то же для 3×3–3×4, ответ вводится цифрами; 2 — «постройка → план»: выбрать план постройки (на плане, нарисованном на «полу» в том же ракурсе, число кубиков на каждой клетке); 3 — «план → постройка»: выбрать постройку по плану (неверные отличаются одной клеткой или двумя переставленными клетками — общее число кубиков может совпадать, поэтому одним счётом не обойтись); 4 — «вид сбоку»: показаны постройка и глаз слева или справа, нужно выбрать, как постройка выглядит с этой стороны (столбики; неверные — вид с другой стороны, зеркальный, с одной ошибкой в высоте). В объёмных постройках спрятанных кубиков нет (`allVisible`). Подсказка при счёте: кубики нумеруются, в остальных заданиях — подсказка-правило, после второй ошибки верный вариант мигает. Задание строится из `seed` (ключ `уровень:seed`).
Генераторы `mental-rotation` и `cubes` проверены на 400–500 зёрен на уровень (задания строятся, у вариантов нет повторов, у «Поворотов» единственный верный).

## Право и лево

Раздел `orientation`, круг `orientation` из двух модулей: пройденный закрывается, когда пройдены оба — супер-наклейка и круг заново.

- `left-right` («Право и лево»): только пчёлка на сетке 3×3 (прежние уровни — предмет слева/справа, ряды, пчёлка в ряду из 5 клеток — убраны по просьбе владельца). Показаны команды ⬅ ➡ ⬆ ⬇, пчёлка в клетке, нужно нажать клетку, куда она придёт (озвучка: налево, направо, вверх, вниз). Старт в случайной клетке, за край не выходит. Уровни — длина пути, не меньше 5 команд: 5 → 5–6 → 6–7. Подсказка после ошибки показывает, где лево и право, и пересказывает команды. Ключ задания — клетка старта и команды, например `4-LDR` (поэтому «трудное» повторяется точно таким же и в конце серии ошибочные задания даются теми же). Старые ключи прежних типов (`side`, `walk`…) в `ctx.hard` игнорируются.
- `left-right-other` («Лево и право другого»): человек стоит лицом к ребёнку — его правая рука там, где у ребёнка левая. Типы: «В какой руке у мамы мяч?» (ответ кнопками «в левой»/«в правой») и «Покажи правую руку папы» (нажать на руку рядом с человеком), каждый — когда человек стоит лицом к ребёнку (`face`) и когда спиной (`back`, чёрный силуэт). Уровни: `hold-face` → + `hand-face` → + спиной → всё вместе. После ошибки под заданием появляется объяснение словами (`hintFace`/`hintBack` в `texts.js`), после двух ошибок верный ответ подсвечивается. Ключи трудных: `hold-face`, `hand-face`, `hold-back`, `hand-back`. Герои и предметы — в `texts.js`.

Уровни: 0 — do и feel, 1 — act, 2 — place, 3 — всё вместе; с уровня 2 неверные картинки отличаются от верной только героем или действием. У двух предложений одного типа не должно быть одинаковой пары эмодзи (`check.mjs` это проверяет). Ключ трудного задания — сам текст предложения. Оба модуля тоже в круге `english`.
- **Круг `english`** — все английские модули (`english-words`, `english-quiz`, `english-say`, `english-phrases`, `english-sentences`) работают как остальные разделы: пройденный закрывается (серая плитка с ✓, «Ещё раз» нет), пока не пройден весь раздел; потом супер-наклейка и круг заново. Правило «у каждого модуля есть `cycle`» `check.mjs` проверяет и для английского.
- Модуль `english-say` («Hello! Скажи слово») — тренирует **вспоминание**, а не узнавание (в `english-quiz` и других нужно выбрать картинку, и ребёнок может хорошо отвечать, но не называть слова сам). Выбор темы (26 тем и «Mix», как в `english-quiz`), потом серия: показана одна картинка (эмодзи-наклейка, цветной кружок или число), ребёнок называет слово вслух; сеть и распознавание речи не используются. Кнопка «Проверить» — слово звучит голосом Sonia и пишется крупно (касание слова повторяет), ребёнок сам отмечает «Получилось!» или «Не получилось». «Не получилось» — слово звучит ещё раз («Скажи вместе со мной!»), потом «Дальше»; слово вернётся в конце серии. Уровни: 0 — на экране первая буква и черточки на каждую букву; 1 — только картинка, кнопка «Подсказка» показывает те же клеточки; 2 — без подсказки. Подсказкой считается и клеточки уровня 0, и нажатая кнопка: с подсказкой ответ не засчитывается как «с первой попытки». Верно с первой попытки трижды подряд — уровень растёт, ошибка — падает. Слова не учитываются под ключом `en:` (его ведёт узнавание в `english-quiz`), а под отдельным **`ens:<слово>`** — «называет вслух»; учёт идёт только с уровня 1 (`KEYED_FROM_LEVEL`), в блоке «Слова» у родителя и в отчёте это отдельная строка («Английские слова (называет вслух)», `STR.parent.vocabSets`). Слова и озвучка общие с `english-words` (`../english-words/words.json`, новых mp3 нет; `files` манифеста обновляет `tools/make_audio.py`). Из слов исключены (`SKIP` в `texts.js`) те, что по одной картинке называют по-разному: `cool`, `love`, `surprised`, `laugh`, `beach`, `movie`. Классы `sy-…`. Родитель может проверять сам: попросить назвать слово вслух вместе с ребёнком.
- Файлы озвучки едут на Хромбук вместе с приложением (GitHub Pages и service worker). Чтобы работать офлайн, они перечислены в `files` манифеста (`../../audio/en/…`).
- Добавили слова в `words.json` — запустите `python tools/make_audio.py` (и `node tools/check.mjs` — он проверяет повторы картинок, озвучку и списки файлов): он создаст недостающие mp3 (пакет `edge-tts`, голоса Microsoft, интернет нужен только при создании) и обновит `files` в манифестах всех пяти английских модулей. Скрипт озвучивает и слова, и сочетания «цвет + предмет» (`phrases.json`), и предложения (`sentences.json`) — после правки любого из трёх файлов запускайте его снова. Если pip ругается на сертификат: `pip install --use-feature=truststore edge-tts truststore` (сначала поставить `truststore`).

## Время в приложении и дневной лимит

- `core/main.js` раз в 5 секунд добавляет время в `usage` (секунды по дням, ключ — местная дата `ГГГГ-ММ-ДД`, `storage.addUsage`). Считается только когда вкладка видна и последнее касание было меньше 90 секунд назад. Экран для родителей и экран отдыха время не считают.
- Статистика на экране «Родителям» («Время в приложении»): сегодня, 7 и 30 дней со средним, список по дням за 30 дней со столбиками. Хранится 400 дней, экспортируется вместе с прогрессом.
- Дневной лимит (`settings.dailyLimit`, минуты, 0 — без ограничения; шаги 15/20/30/45/60/90/120/180). Когда время вышло, на меню, наклейках и при запуске модуля показывается экран `core/screens/limit.js` («На сегодня достаточно!») с кнопкой «Родителям». Если лимит вышел посреди задания, его дают закончить: блокировка наступает через 5 минут сверх лимита (`GRACE_MIN`) или когда ребёнок выходит в меню. Утром, в новый день, блокировка снимается сама.
- Когда время вышло, родитель на экране «Родителям» в блоке «Время на сегодня» нажимает «Ещё 15 минут», «Начать лимит заново» или «Снять лимит на сегодня» — это дополнительные минуты на текущий день (`storage.setBonus`, лимит на сегодня = `todayLimit()`), поэтому статистика времени остаётся точной, а завтра действует обычный лимит. Пока ничего не нажато, «Назад» снова ведёт на экран отдыха.
- Вход на экран «Родителям» (из меню и с экрана отдыха) закрыт проверкой «только для взрослых» (`core/screens/gate.js`): нужно решить пример на умножение (6–9 × 6–9) цифрами на экране или клавиатуре; при ошибке новый пример, после 3 ошибок подряд пауза 30 секунд. Перерисовка самого экрана родителя (после кнопок на нём) проверку не повторяет. Это защита от случайных входов, не от подросшего ребёнка, который выучил таблицу умножения.

## Уровни, слова, артикли, ввод цифрами

- **Уровень помнится между сериями** (`progress[id].level`, `ctx.level`, см. таблицу контракта): серия начинается на уровень ниже достигнутого, повышение — после 3 верных подряд. Во всех 22 модулях с уровнями `let level = Math.min(ctx.level ?? START, <число уровней> - 1)` и `ctx.finish({ …, level })`. Новый модуль с уровнями должен делать так же.
- **Учёт слов** (`core/storage.js`: `recordWord`, `wordInfo`, `wordWeight`, `wordSummary`, `wordList`; состояние `words` и `vocab`): у слова с ключом `ru:кот` / `de:Hund` / `en:cat` / `de-art:Hund` хранится число верных подряд с первой попытки (`s`), попыток (`n`), верных (`ok`), время последнего ответа (`t`). Выучено (`known`), когда верных подряд ≥ `KNOWN_STREAK` = 2; такое слово не выпадает, пока не пройдёт срок повторения (`REVIEW_DAYS`: 14, 30, 60, 120 дней; потом — `due`, вес 1,5). Веса выбора: новое 3, учится 4, пора повторить 1,5, выучено 0 (если все кандидаты выучены — выбирается любое). Ошибка обнуляет серию. Подключено в `reading-ru`, `reading-de`, `reading-pick`, `reading-pick-de` (только задания-слова), `english-quiz`, `german-articles`: модуль выбирает слово через `ctx.words.pick(...)` и передаёт `key` в `ctx.task`. Слова фраз и предложений не отслеживаются. «Сбросить прогресс» стирает и учёт слов (он часть прогресса); на экране «Родителям» — блок «Слова: что знает ребёнок», в отчёте — раздел «Слова».
- **`german-articles` («Der, die oder das?»)**, круг `german`: слово с картинкой, нужно выбрать артикль der/die/das (цвета: der синий, die розовый, das зелёный). Уровни: 0 — два артикля на выбор, частые слова (`easy`), цветные кнопки; 1 — три артикля, цветные; 2 — без цветов; 3 — без цветов и без картинки (только слово). После ошибки кнопки становятся цветными, после второй — подсвечивается верный артикль. `data.js`: 268 существительных (der 96, die 99, das 73), артикль указан явно — при добавлении слов проверять род по словарю; `check.mjs` ищет повторы слов и картинок.
- **Ввод цифрами** (`modules/addition-10/keypad.js` + `keypad.css`, подключены в `addition-10/20`, `subtraction-10/20` — исключение из правила «модуль самодостаточен», как у `english-quiz`): с уровня `INPUT_FROM_LEVEL` = 2 вместо трёх вариантов показывается клавиатура 0–9 и ⌫; ответ отправляется сам, когда набрано столько цифр, сколько в верном ответе. Неверный ввод — «?» вздрагивает, поле очищается, считается ошибкой (подсказка как у выбора). Клавиатура помещается на 1024×600.

## Журнал серий и отчёт для анализа

Чтобы оценивать, насколько легки или сложны задания, и готовить новые этапы, приложение ведёт журнал серий и по кнопке «📋 Отчёт для анализа» (экран «Родителям», блок «Данные») сохраняет markdown-файл `moya-shkola-otchet-ГГГГ-ММ-ДД.md`. Его раз в 1–2 недели отдают Claude Code: «проанализируй отчёт и предложи, как усложнить задания». Сеть не нужна, данные остаются на устройстве.

- `core/journal.js`: запись на серию в `localStorage` под ключом `school-app-journal-v1` (читает/пишет `storage.readJournalText/writeJournalText`; основное сохранение не раздувается, «Сбросить прогресс» журнал не стирает). Последние 2000 серий. Запись: `{ t, id, sub, len, ok, done, sec, off, ch, tag, tasks: [[уровень, верно, мс], …], miss: [ключи] }`. `done: 0` — ребёнок вышел до конца серии (пишется, если было хотя бы одно задание); `ch: 1` — сложное задание (`tag` — id рассказа, `id` — `challenge`, `sub` — раздел). Время задания — от конца прошлого задания, пауза дольше 3 минут обрезается.
- Подключение в `core/main.js` (`play()`): сессия создаётся перед `mod.start`, `ctx.task` → `journal.task`, `ctx.finish` → `journal.finish`, уход с экрана без `finish` → `journal.abandon`. Во всех модулях с уровнями (22) после `const firstTry = await playTask(...)` стоит `ctx.task({ ok: firstTry, level })`. Новый модуль с уровнями должен делать то же; без этого вызова журнал всё равно получит итог серии, но не уровни и время заданий. `english-words` (знакомство) серий не пишет.
- `core/report.js` (`buildReport(app)`): шапка-инструкция для Claude Code (контекст ребёнка, режим 0,5 ч будни / 1,5 ч выходные, цель — ускорить прогресс, что просим), сводка по всем разделам и модулям (серий всего и за 14 дней, точность с первой попытки, медиана и p90 времени на задание, брошенные серии, вывод «легко / в самый раз / сложно / на границе / мало данных» — пороги 93%, 70%, 60%, мин. 20 заданий), по каждому модулю — задания по уровням, уровень на конец серии, точность по неделям, частые ошибки и текущие «трудные»; сложные задания; время в приложении по дням (будни и выходные); сырые строки серий за 28 дней в CSV (списки внутри поля через `;`). Тексты — `STR.report` в `core/strings.js`; пороги и формат правятся в `core/report.js`.

## Ежедневная миссия «Уборка комнаты» (в разработке, ТЗ — `design/room-mission-spec.md`)

Сделаны этап 1 (данные, логика, охрана экранов), этап 2 (рисунок комнаты, виды A и B) и этап 3 (диалог с собакой, выбор зоны, зов взрослого, вопрос взрослому, подарок) этап 4 (таймер с дугой) и этап 5 (собака в комнате делает вид, что убирается) этап 7 (карточка родителя, пробный запуск) и этап 8 (раздел в отчёте для анализа); подарок — косточка (этап 6) и пропуск за звёзды; осталась финальная проверка (этап 9). По умолчанию **выключена** (`settings.mission.enabled`; включается пока только правкой сохранения, карточка у родителя — этап 7).

- `core/mission-data.js` — данные без импортов (чтобы не было цикла с `storage.js`): `ZONES` (семь зон, `view` A/B), `PHASES`, `REWARD` (= косточка, `{ type: 'bones', amount: 1 }`), `REWARD_TYPES`, `SKIP_COST` (= 100 звёзд), помощники дней (`isoWeekday`, `shiftDay`, `continuesStreak`). `core/mission.js` — `missionPending()` и переходы фаз `choose → timer → wait → done | skipped` (`chooseZone`, `startTimer`, `markCleaned`, `addTime`, `confirmDone`, `skipToday`), `msLeft`, `timerProgress`, `currentStreak`. Таймер хранится как момент окончания `endsAt`.
- Хранилище (`core/storage.js`): `settings.mission` (`enabled`, `minutes` 3–15, `days` 1–7), `state.mission` (+ поле `cleanedAt` — когда ребёнок нажала «Я убралась!», для времени уборки в истории), `state.missionUsage`; API `mission()`, `setMission(patch)`, `completeMission(reward)` (атомарно, второй раз за день `false`), `skipMission()`, `addMissionUsage`, `missionUsageOn/Days`. Новый день сам заводит новую миссию (`rollMission`): недоделанная вчерашняя сгорает, серия и история (60 дней) остаются. `reset()` стирает миссию и её время, настройки сохраняет; формат `school-app-v1` и `DOGS_VERSION` не менялись, старое сохранение читается без сброса. `setSettings({ mission: { enabled: true } })` сливает поля с текущими.
- Охрана (`core/main.js`): `showMenu`, `showStickers`, `showDog('real')`, `play` после проверки лимита зовут `showMission()`, если `missionPending()`. Приоритет: экран отдыха (лимит вышел) → миссия → экран. Тестовая собака родителя миссией не закрывается. Экран `'mission'` время в `usage` (дневной лимит) не пишет, а в `missionUsage`; пока идёт таймер, простой не считается (ребёнок убирает и экрана не касается). Проверка для взрослых (`gate`) время не считает нигде.
- **Экраны (этап 3)** — `core/screens/mission.js`: `renderMission(app)` → `{ el, onLeave }`, страницу сам выбирает по фазе (`next()`), «страницы» меняются внутри `.mission-holder` (проверка умножением `renderGate` встраивается туда же). Разворот книги (`createBook`): слева комната (`drawRoom`, выбранная зона светится классом `.hi` — `drop-shadow` на небольших группах) и собака с облачком, справа ответы ребёнка. `choose` — семь карточек зон (выбор можно менять, он сразу пишется в хранилище; зона 6 `kallax` переключает комнату на вид B, остальные — вид A) и «Начнём!» (серая, пока зона не выбрана); `timer` — уборка с таймером (этап 4, ниже): дуга, время, реплики собаки, «Я убралась!» (собака в комнате — этап 5, ниже); `wait` — «Позови маму или папу» → «Позвать взрослого» → проверка → вопрос взрослому (зона, потраченное время, «Да, убрано» / «Ещё нет — добавить N мин.» / «Пропустить сегодня», «Назад»); подарок — радующаяся собака, косточка с отскоком и «Косточек на счету: N» (`giftView`; саму косточку выдаёт `storage.completeMission` вместе с закрытием дня, `applyReward`). Замок «Для родителей» (→ проверка → экран родителя, «Назад» возвращает на страницу по фазе). У ребёнка кнопок «домой» и «пропустить» нет. **Таймер (этап 4, `cleanView`):** золотая дуга убывает, в центре `m:сс` (`Math.ceil`), под ней зона. Время — только `msLeft()` по `endsAt` (тик 500 мс лишь перерисовывает; перезагрузка и возврат во вкладку ничего не сбивают; в скрытой вкладке `paint` не рисует, при `visibilitychange` перерисовывает сразу). Реплика собаки: «Я помогаю…» → «Уже половина!» (осталось ≤ половины отрезка) → «Скоро время!» (≤ 60 с) → «Время вышло!»; в момент истечения на экране один раз мягкий `done` (если экран открыт уже после истечения — без звука). Время вышло — таймер не блокирует и не обнуляется, «Я убралась!» есть всегда. `timerProgress()` считает от оставшегося времени, а не от `startedAt`: после «Ещё нет — добавить N мин.» (`endsAt = сейчас + N`) отрезок и дуга начинаются заново, а `startedAt` остаётся для истории. Экран не гаснет: Screen Wake Lock (`keepAwake`, берётся заново при возврате в вкладку, отпускается при уходе с экрана). Фильтров на дуге нет — она перерисовывается каждую секунду. Время миссии (`missionUsage`) в фазе таймера идёт и без касаний (проверено 125 с без касаний). **Собака в таймере (этап 5):** `core/screens/mission-dog.js` (`createRoomDog`) и расписание `dogPlan()` в `core/mission.js`. Собака «делает вид, что убирается»: 6 с идёт от двери к точке зоны (`stand[вид]` в `ZONES`, единицы кадра комнаты 380×250; `spot[вид]` — центр зоны для искорок), дальше по кругу 12 с работает (жест зоны `gesture`: `wipe` — лапа, `sweep` — голова и корпус, `tidy` — кивает, `nudge` — подталкивает) и 4 с отдыхает, в последние 15 с (и после конца таймера) гордо сидит с поднятой головой. Вокруг центра зоны (`spot`) по мере уборки прибавляются 7 искорок «чисто», в конце горят все. Расписание зависит только от `elapsed`/`left` (не от хранимого состояния): после перезагрузки собака сразу на месте, после «Ещё нет» (`extra > 0`) не идёт от двери заново. Движение — `transform` внешней группы (`.mz-walker`, плавный ход 0,55 с включается только после первой расстановки), фильтр `wcDog` внутри неподвижен; жесты — анимации частей рисунка (`.dog-paw-r`, `.dog-head`), классы `.mz-actor.g-*` в `mission.css`. Зоны хранят `view` (вид по умолчанию), `views` (где зона видна: пол, кровать и диван — в обоих видах) и точки собаки по видам; `check.mjs` сверяет `views` с тем, где зона реально нарисована. Новые бесконечные анимации (`.mz-actor`, `.mz-spark`) добавлены в список остановки в `book.css` (`app-idle`); при `prefers-reduced-motion` собака стоит у зоны без движения. На экране таймера собаки под комнатой нет, облачко на всю ширину. Позже, когда появится беспорядок (ТЗ 8.8), пантомима заменится переносом предметов.
**Ручной вид комнаты:** кнопка «↻ Повернуть» в углу комнаты (на всех страницах миссии, включая таймер) переключает вид A ↔ B; ручной вид держится, пока открыт экран миссии. Если выбрать зону, которой нет в выбранном вручную виде, вид сам возвращается к тому, где зона видна; в таймере в виде без зоны собака и искорки скрыты (время идёт как шло), при смене вида собака сразу встаёт на место (`update({ view })` в `mission-dog.js`). Подсветка выбранной зоны (`.hi`) — яркое золотое свечение из четырёх `drop-shadow` и `brightness`.

Ребёнок может **сама пропустить уборку за `SKIP_COST` = 100 звёзд**: кнопка-записка «Пропустить: 100 ⭐» вверху страницы выбора зоны; не хватает звёзд — собака объясняет («нужно 100 звёзд, у тебя N»); хватает — окно подтверждения («Нет, буду убираться» крупнее и главная, «Да, пропустить»), затем экран «−100 ⭐» и «К заданиям». `storage.skipMissionPaid(cost)`: списывается с баланса (`spent += cost`; заработанные звёзды и отсчёт сложных заданий не уменьшаются), фаза `skipped`, в истории `paid: 100`, подарка нет; в пробном запуске ничего не тратится. Пропуск взрослым (`paid: 0`) остаётся бесплатным. В карточке родителя и в отчёте пропуск за звёзды помечен («пропущена ребёнком за 100 ⭐», колонка `потрачено_звёзд` в CSV миссии).

## День рождения ребёнка (поздравление от собаки)

Собака поздравляет ребёнка в день рождения: экран `core/screens/birthday.js` (разворот книги, как у миссии «Уборка комнаты»; логика — `core/birthday.js`, данные и даты без импортов — `core/birthday-data.js`, стили — `core/styles/birthday.css`). Три шага: (1) собака в праздничном колпаке, гирлянда, шарики, конфетти, возраст, поздравление по-русски в облачке и «Alles Gute zum Geburtstag» на карточке; (2) торт со свечками по числу лет (до 10, больше семи — две строки): каждая гасится касанием, когда погасли все — мелодия «Happy Birthday» (`PATTERNS.birthday` в `core/sounds.js`, WebAudio, файлов нет); (3) три коробки с подарками: 5 косточек, праздничный колпак, наклейка. Все подарки выдаются **один раз за год** при первой открытой коробке (`storage.claimBirthday`): `GIFT` в `birthday-data.js` — косточки в рабочий набор, колпак `party` в вещи и надет на собак без шапки, наклейка — первая ещё не собранная из `GIFT.stickers` (`sweets-5` — торт 🎂, дальше `party-0…3`; если все есть — звёзды).

- **Настройки** (`settings.birthday`: `enabled`, `name`, `month`, `day`, `year` — год рождения, по нему считается возраст). По умолчанию **включено**: Алиса, 12 ноября, 2019 (значения по умолчанию — `DEFAULT_BIRTHDAY` в `birthday-data.js`; старое сохранение без поля читается с ними). Родитель меняет их на вкладке «Настройки» (карточка «День рождения ребёнка»). Отметка «за какой год уже отпраздновано» — `state.birthdayDone` (год); сброс прогресса её не трогает, чтобы подарки не выдавались второй раз.
- **Когда показывается**: в сам день рождения и ещё `LATE_DAYS` = 2 дня после него, если приложение не открывали (текст «Вчера был твой день рождения!»); пока подарки не получены. Охрана — в `core/main.js` (`showMenu`, `showStickers`, `showDog('real')`, `play`): порядок «экран отдыха (лимит) → поздравление → миссия → экран». Время на экране поздравления дневной лимит не расходует (`screenKind === 'birthday'`).
- **Уборка комнаты в день рождения не нужна**: `missionPending()` возвращает `false`, когда сегодня день рождения (`birthdayToday`); при получении подарков в сам день рождения открытая миссия закрывается как «пропуск» (`paid: 0`) и серия подряд идущих дней не прерывается. В «догоняющие» дни (1–2 после) уборка остаётся.
- **Проверка из раздела для родителя** (вкладка «🧪 Тестировщик»): «Показать поздравление» (`app.go.birthdayTest`, пробный показ: подарки не выдаются, ничего не записывается, «Выйти из проверки» возвращает на экран родителя) и «Вернуть поздравление этого года» (`storage.reopenBirthday`; выданные подарки не возвращаются).
- `node tools/check.mjs` проверяет даты (включая 31 декабря и 29 февраля), настройки по умолчанию и плохие значения, выдачу подарков раз в год, колпак на собаку, отсутствие уборки в этот день, наличие файлов в `CORE_FILES`. Старые проверки миссии отключают поздравление через `importData`: иначе 12–14 ноября миссии в тесте не было бы.
- Новое событие дня (другой праздник) — по тому же образцу: данные и даты отдельным файлом, охрана в `main.js`, экран в `core/screens/`.

## Проверка проекта

`node tools/check.mjs` — быстрая проверка без браузера: синтаксис, импорты, манифесты и реестр, офлайн-кэш (`sw.js`, поле `files`), опасные паттерны, а также банки русского и немецкого (повторы слов и картинок в `words.js` — они там тихо отбрасываются, повторы предметов в `data.js`, одинаковые предложения, повтор слова внутри предложения, одинаковая картинка у двух предложений одного вида и перекос по словам — см. «Банки предложений и контроль повторов слов»). Запускайте перед отправкой на GitHub; при ошибках скрипт перечисляет их с путями.

Размер банков: слов для чтения — русский 349, немецкий 318 (картинки у всех разные, до 10 букв; новые слова дописываются в `PAIRS` в `words.js`, `check.mjs` сообщает о повторах); предметов для «двух слов» — 65 и 68; предложений — 711 и 836 (см. раздел «Банки предложений и контроль повторов слов»). Новые слова и предложения дописываются в списки (`PAIRS`, `NOUNS`, `SUBJECTS`); у одного героя на одну картинку-место или картинку-предмет — одно действие, иначе предложения с одинаковой картинкой станут неоднозначными. Слова для чтения — до 10 букв, предметы для «двух слов» — до 7.
